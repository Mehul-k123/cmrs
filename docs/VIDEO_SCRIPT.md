# 5-minute explanation video: outline

Target ≈ 4:45. Timings are cumulative. Keep the app open in two browser profiles (agent and branch manager) to save time.

| Time | Section | What to say / show |
|---|---|---|
| 0:00–0:25 | **Problem** | Field agents collect cash for loan EMIs. Money moves Customer → Agent → Branch → Bank → Company account, and each hop can leak. CMRS makes every rupee traceable and every difference visible. |
| 0:25–1:00 | **Architecture** | README diagram: React SPA (Vite + TS) → DRF REST API with JWT → service layer → PostgreSQL. Views stay thin; all business rules live in `services.py` and run in transactions with row locks. Deployed on Render (API + static site + Postgres). |
| 1:00–1:35 | **Database** | SCHEMA.md ER diagram. Collection is the atomic unit; allocations split it across installments; submissions and deposits batch it. NUMERIC(14,2) everywhere, DB check constraints (`0 ≤ paid ≤ due`), unique (bank, reference), PROTECT on financial FKs, append-only audit log. |
| 1:35–3:30 | **Demo** (key workflows) | 1. **Agent** (agent.priya): Record Collection → partial ₹777.50 → receipt with EMI split. Re-enter the same amount → *possible duplicate* warning. Try more than outstanding → blocked. Submit Cash → select all. 2. **BM** (bm.mumbai): Cash Submissions → Verify → type ₹100 less → difference shows, reason required → approve → Discrepancies page shows the shortage. Bank Deposits → new deposit → try a reused reference → 409. 3. **Finance**: Deposits → delayed badge on the Pune deposit → Reconcile → settle. Dashboard: lifecycle bars and KPIs move; filter by branch or agent. Audit log shows before/after. 4. Loan detail → UPI payment link → "Customer pays" → receipt; the UPI collection skips agent/branch custody and settles when Finance runs the gateway settlement. |
| 3:30–4:05 | **Business rules & trade-offs** | Over-collection rejected (no advance/refund flow). Shortage approved at the received amount plus a discrepancy, rather than blocking. Rejection returns custody to the agent. Reconciled collections are locked at API, model and admin levels; only an Admin reversal with an adjustment discrepancy can undo them. Status columns plus an audit log instead of a full double-entry ledger, for simplicity. No Celery: one cron command covers the async need. |
| 4:05–4:25 | **Challenges** | Idempotency vs. genuine second payments (two separate mechanisms). Concurrency (`select_for_update`). Keeping money exact in the UI (integer-paise preview, server totals). |
| 4:25–4:50 | **With more time** | Double-entry ledger; bank-statement file import with auto-matching; real Razorpay sandbox; agent GPS/offline-first PWA; maker-checker for reversals; Playwright E2E in CI; per-role dashboards with exports. |
